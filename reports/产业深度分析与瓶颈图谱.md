## 二、瓶颈判定：从「算公式」改为「讲事实」

**v1 与 v2 都失败过**：
- v1 用 `(1/上游) × (1+下游)`，把「只有一个客户的叶子节点」算成最高瓶颈
- v2 改成「上游少且下游多」，但图谱太稀疏，多数节点都是「上游1、下游1」，
  指数全部等于 4.00，**完全无法排序**

**v3（本轮）改为事实优先**：瓶颈由产业事实直接判定，图谱只用于展示传导路径。
每条瓶颈都带依据，可追溯。

## 四、实测最长传导链

```
云南锗业 → Lumentum → 源杰科技 → 新易盛 → 北美云厂商   （4 跳）
```

**含义**：磷化铟衬底断供，要传 4 跳才影响终端云厂，但**每一跳都在放大**——
实际影响不是衰减，而是**短缺沿链累积**。这是当前衰减模型（0.55^跳）的盲区。

## 六、UI 改进

侧栏内容变长后，产业瓶颈曾被挤到很下面。本轮调整为：
**瓶颈 → 冲击 → 产业图谱 → 供应链 → 研报底座 → 待补材料**，
并把每个产业/场景改为可折叠（`<details>`），默认只展开第一个。

## 七、已知局限

1. **89 条关系没有一条经财报验证**——全部来自会议转记与产业笔记；
2. **衰减模型方向单一**：只做 0.55^跳，但真实短缺会沿链**放大**（Accumulation）；
3. **没有份额数据**：只能判断「有无关系」，不能判断「影响多大」；
4. **没有时间维度**：不知道事件何时发生、传导需要多久。
